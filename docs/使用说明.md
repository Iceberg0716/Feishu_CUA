# 项目使用说明

## 1. 项目简介

本项目是一个基于视觉模型的桌面自动化代理，当前主要面向飞书 / Lark 桌面端。

当前主流程：

1. 截图当前桌面
2. 调用 VLM 分析界面并生成动作
3. 执行动作
4. 再次截图并做结果验证
5. 失败时尝试恢复到稳定模块并重试

当前已经支持的保护机制：

- 用户输入空闲等待
- 目标窗口聚焦
- 页面状态识别
- 恢复到稳定模块
- 失败后有限次重跑
- 按步骤精确删除截图

## 2. 运行前提

要正常运行，必须满足下面条件：

- 操作系统建议为 Windows
- 机器上已安装 Python 3.10 或以上版本
- 有真实桌面环境，不能是纯无头环境
- 飞书 / Lark 客户端已经打开
- 当前机器可以访问配置的 VLM 接口
- `DASHSCOPE_API_KEY` 有效，或你已在配置里填入有效 key

说明：

- 本项目当前不是浏览器自动化，也不是 DOM 自动化，而是桌面截图 + 鼠标键盘模拟。
- 如果用户在执行过程中持续操作鼠标键盘，程序会等待空闲，或者导致识别结果与执行时刻不一致。

## 5. 主要参数说明

下面是当前最重要的配置项。

### 5.1 接口与日志

```python
log_dir = "logs"
screenshot_dir = "logs/screenshots"
trace_file = "logs/trace.jsonl"
```

- `log_dir`：日志根目录
- `screenshot_dir`：截图存储目录
- `trace_file`：每一步执行记录写入的 JSONL 文件

### 5.2 动作执行延迟

```python
action_delay_min = 0.3
action_delay_max = 0.8
```

- 控制鼠标点击、双击、输入、快捷键、滚动之前的随机延迟
- 数值越小，动作越快；数值越大，动作越稳但整体更慢

### 5.3 用户输入空闲检测

```python
input_idle_timeout_s = 1.0
input_poll_interval_s = 0.05
post_action_settle_timeout_s = 2.0
post_action_settle_poll_s = 0.2
```

- `input_idle_timeout_s`：执行前要求用户输入静止的时长
- `input_poll_interval_s`：检测鼠标/键盘活动的轮询间隔
- `post_action_settle_timeout_s`：动作执行后等待界面稳定的时间窗口
- `post_action_settle_poll_s`：动作执行后的稳定性轮询间隔

建议：

- 如果用户容易误碰鼠标，可把 `input_idle_timeout_s` 调到 `1.5` 或 `2.0`
- 如果界面跳转较慢，可把 `post_action_settle_timeout_s` 调到 `3.0`

### 5.4 截图保留策略

```python
screenshot_keep_failed = True
screenshot_keep_passed = False
screenshot_keep_latest_sessions = 3
screenshot_keep_max_age_hours = 24
```

- `screenshot_keep_failed`：失败步骤是否保留截图
- `screenshot_keep_passed`：成功步骤是否保留截图
- `screenshot_keep_latest_sessions`：保留最近多少个截图会话目录
- `screenshot_keep_max_age_hours`：超过多少小时的旧会话允许被清理

推荐默认值：

- 调试阶段：保留失败截图，删除成功截图
- 回归测试阶段：成功截图也可保留，便于复盘

### 5.5 窗口聚焦与页面恢复

```python
target_app_names = ("Feishu", "Lark", "飞书")
stable_home_state = "messages"
known_page_states = (
    "messages",
    "calendar",
    "docs",
    "sheets",
    "meetings",
    "mail",
    "knowledge",
    "unknown",
)
recovery_max_attempts = 2
state_navigation_hotkeys = {
    "messages": ["ctrl", "1"],
    "calendar": ["ctrl", "2"],
    "docs": ["ctrl", "3"],
    "sheets": ["ctrl", "3"],
    "meetings": ["ctrl", "4"],
    "mail": ["ctrl", "5"],
    "knowledge": ["ctrl", "6"],
}
```

- `target_app_names`：用于匹配窗口标题的关键字
- `stable_home_state`：失败恢复时默认回到的稳定模块
- `known_page_states`：当前支持识别的页面状态
- `recovery_max_attempts`：失败后自动恢复并重试的最大次数
- `state_navigation_hotkeys`：不同模块的快捷键导航配置

注意：

- 如果你的飞书快捷键不是默认 `Ctrl+数字`，需要修改 `state_navigation_hotkeys`
- 如果你的窗口标题不包含 `Feishu`、`Lark` 或 `飞书`，需要修改 `target_app_names`

### 5.6 VLM 定位与确认

```python
localization_mode = "full_window"
preclick_confirmation = True
```

- `localization_mode`：VLM 定位模式
  - `"full_window"`（默认）：直接在完整窗口截图上让 VLM 定位目标元素，一步到位
  - `"region"`：先分区分析确定目标区域，再在该区域内精确定位（二阶段，适合大屏）
- `preclick_confirmation`：点击前是否做目标确认
  - 开启后，执行 click 前会在目标点周围裁剪 80×80 像素补丁，交由 VLM 二次确认是否为正确元素
  - 如果确认失败（VLM 识别到的元素与指令不匹配），会触发重试/回退
  - 建议保持默认开启，可有效避免误点击

## 9. 运行输出怎么看

程序执行过程中，当前常见输出包括：

- `[STATE]`：页面状态识别结果
- `[STATE-RECOVERED]`：恢复后的页面状态识别结果
- `[VLM] thought`：视觉模型的分析思路
- `[VLM] action`：视觉模型给出的动作
- `[RETRY]`：验证失败后进行自动重跑
- `[RETRY-ERROR]`：发生异常后先恢复再重跑

关注重点：

- `state`
- `verdict_passed`
- `verdict_reason`
- `recovery_reason`
- `attempts`

## 10. 日志与截图说明

### 10.1 执行日志

每一行是一条 JSON 记录，包含：

- 动作结构
- 验证结果

### 10.2 截图目录

截图会保存到：

```text

```

每个会话目录内包含：

- `before` / `after` 截图
- `index.json`

### 10.3 删除策略

- 成功步骤默认删除当前步骤截图
- 失败步骤默认保留当前步骤截图
- 旧会话目录按保留数量和最大保留时长清理

## 11. 当前能力边界

当前项目已经比最初稳定，但仍有明显边界：

- 依赖 VLM 对截图的理解准确率
- 依赖目标窗口标题能够被正确匹配
- 依赖飞书模块快捷键与当前配置一致
- 当前恢复是“回稳定模块再重跑”，还不是完整的任务规划器
- 中文/非 ASCII 输入通过剪贴板粘贴实现（先清空输入框再 Ctrl+V），纯 ASCII 仍用键盘模拟
- 复杂多步任务仍可能需要继续扩展状态机和导航策略

## 12. 推荐测试顺序

## 13. 常见问题

### 13.1 程序没有动作

排查：

- 是否设置了有效的 `DASHSCOPE_API_KEY`
- 当前屏幕上是否真的显示了飞书 / Lark
- 用户是否一直在移动鼠标或打字
- 目标窗口标题是否匹配 `target_app_names`

### 13.2 总是恢复失败

排查：

- 飞书窗口是否已经打开
- 飞书窗口标题是否包含 `Feishu`、`Lark`、`飞书`
- 本地模块快捷键是否和 `state_navigation_hotkeys` 一致

### 13.3 验证总失败，但界面其实已经变了

排查：

- 可适当增大 `post_action_settle_timeout_s`
- 也可以保留成功截图，核对 before / after 差异
- 某些界面变化较轻微，VLM 验证可能需要进一步优化 prompt

### 13.4 中文输入变成数字或乱码

排查：

- 确认已安装 `pyperclip`（`pip install pyperclip`）
- 非 ASCII 输入现在通过剪贴板粘贴，不再模拟键盘按键
- 如果输入框中有残留字符，程序会自动先 Ctrl+A → Backspace 清空再粘贴
