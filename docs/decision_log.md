# 决策记录

## 2026-04-29

### 文档更新机制

- 决策：每轮结束后更新项目文档。
- 决策：新一轮开始默认不主动读文档，优先用当前上下文。
- 原因：兼顾持久化记忆与 token 成本。

### 运行期人工干预处理

- 决策：不锁死用户输入。
- 决策：在执行前、执行后截图前等待输入稳定。
- 原因：桌面自动化需要和真实用户环境共存，强行锁输入风险更高。

### 截图管理

- 决策：截图按会话目录管理。
- 决策：只按步骤精确删除截图，失败步骤默认保留。
- 原因：既控制存储增长，也保留排障证据。

### 窗口、状态与恢复

- 决策：执行前先聚焦目标应用，不假设飞书已在前台。
- 决策：页面未知或验证失败时先恢复到稳定模块再重试。
- 原因：项目早期先补稳定性骨架，再逐步提升通用性。

### 知识外置

- 决策：把飞书相关硬编码迁移到 `knowledge/feishu.json`。
- 原因：环境知识、导航知识、恢复知识都不适合长期写死在代码里。

## 2026-04-30

### 借鉴 ShowUI / LLaVA-VLA 的方式

- 决策：不直接拼接两个开源项目，而是分层吸收思路。
- 决策：不做模型微调，所有增强走 runtime 路线。
- ShowUI 主要借鉴：
  - 前台窗口裁剪
  - 分区分析
  - 二阶段定位
- LLaVA-VLA 主要借鉴：
  - 动作 schema
  - `ActionChunk`
  - 短动作片段执行

### 模板系统

- 决策：常见任务优先走知识库模板，命中模板时可跳过 VLM。
- 决策：模板支持 `allowed_states` 和 `slots`。
- 原因：对高频、稳定任务，模板路径更快也更可控。

### 模板前后条件

- 决策：模板新增 `preconditions` 和 `postconditions`。
- 决策：前置条件不满足时不命中模板，直接回退到 VLM。
- 决策：后置条件失败时先恢复，再回退到 VLM。
- 原因：模板必须同时回答“何时可执行”和“执行后是否真的成功”，否则只是更快的硬编码分支。

### 测试策略

- 决策：保留现有无模型闭环回归测试，同时补基础层单元测试。
- 单元测试覆盖：
  - 动作解析
  - 知识库加载
  - 截图分区与索引更新
  - 恢复逻辑
- 原因：当前项目已经有较多知识库和 runtime 分支，只靠一条 smoke test 不足以防回归。

## 2026-05-02

### 定位模式与点击确认

- 决策：默认使用 `full_window` 全屏定位模式，保留 `region` 分区域模式作为备选。
- 决策：默认开启 `preclick_confirmation`（点击前 80x80 补丁由 VLM 二次确认）。
- 原因：全屏定位一步到位，减少了分区分析的额外 VLM 调用；点击确认可有效避免误点击导致后续连锁失败。

### 中文输入方案

- 决策：非 ASCII 字符改用剪贴板粘贴（`pyperclip.copy` + `Ctrl+V`），纯 ASCII 仍用 `pyautogui.typewrite` 模拟。
- 决策：粘贴前先 `Ctrl+A` → `Backspace` 清空输入框。
- 原因：`pyautogui.typewrite` 基于虚拟键码，中文字符不在键码表中；清空输入框防止残留字符混入。

### VLM 小图像保护

- 决策：截图/裁剪结果 <20px 时回退到全屏或返回安全默认值，不发送给 VLM。
- 原因：VLM API 对极小图像（<10px/维度）返回 400 错误，恢复流程中可能截取到 toast/通知类极小程序窗。

### 滚动光标定位

- 决策：`ScrollAction` 增加 `x`/`y` 字段，滚轮操作前先移动光标到指定坐标。
- 原因：`pyautogui.scroll` 在光标不在可滚动区域时无效果，需要前置光标定位。

### ActionChunk 确认递归

- 决策：`_confirm_click_target` 对 ActionChunk 递归提取第一个 click 子动作做确认，而非直接返回 True。
- 原因：复合动作块中第一个 click 通常是最关键的定位操作，跳过确认等同于关闭了整个 ActionChunk 的安全校验。
