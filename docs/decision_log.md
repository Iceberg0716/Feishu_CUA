# 决策记录

## 2026-04-29

### 本轮规则：实时更新文档

- 决策：每一轮结束后更新项目文档。
- 约束：新一轮开始时不默认读取文档，除非用于恢复上下文或核对历史状态。
- 原因：在保留持久化项目记忆的同时，控制 token 消耗。

### 运行过程中的人工干预处理

- 决策：不采用全局禁用用户输入的方式。
- 决策：在执行动作前、执行后截图前，等待鼠标和键盘进入空闲状态。
- 原因：强行锁定桌面输入风险更高，也更不利于桌面自动化场景的稳定运行。

### 截图删除策略

- 决策：截图按会话组织，而不是存放在单一平铺目录中。
- 决策：截图删除按步骤粒度执行，而不是按目录粒度执行。
- 决策：默认保留失败步骤截图，默认删除成功步骤截图。
- 原因：这样既能控制存储增长，又不会误删排障所需证据。

### 起始状态与失败恢复骨架

- 决策：在主流程执行前先尝试聚焦目标应用窗口，而不是假设目标应用已经在前台。
- 决策：如果当前没有找到飞书窗口，先尝试直接启动飞书，再继续聚焦与恢复。
- 决策：在动作规划前先进行页面状态识别，作为后续导航与恢复的基础。
- 决策：当页面状态未知或验证失败时，先执行一轮保守恢复骨架，而不是直接继续点击。
- 决策：恢复后要导航到稳定模块，而不是只停留在 `Esc` 收敛状态。
- 决策：验证失败后要自动重跑当前任务，但重跑次数受配置限制。
- 当前恢复策略：聚焦目标窗口后发送 `Esc`，再通过预设快捷键导航到稳定模块。
- 原因：当前项目尚未具备真正的多步导航能力，先补足最基础的状态感知与可恢复性。

### 知识外置

- 决策：将飞书相关硬编码知识从代码中抽离到 `knowledge/feishu.json`。
- 当前外置内容：应用名称、启动命令、已知页面状态、稳定模块、模块导航快捷键。
- 原因：这类知识会随环境、版本和用户习惯变化，不适合长期写死在代码里。

### ShowUI 与 LLaVA-VLA 的组合吸收策略

- 决策：不直接尝试拼接两个开源项目的完整实现。
- 决策：按层吸收各自优势，而不是按仓库整体迁移。
- 决策：在当前项目中不进行模型微调。
- ShowUI 主要借鉴方向：
  - 局部化视觉
  - 分区分析
  - 二阶段 grounding
  - 更经济的视觉推理
- LLaVA-VLA 主要借鉴方向：
  - 动作正式建模
  - action chunk
  - 历史状态与动作轨迹输入
  - 统一数据格式用于回放、评测和运行时优化
- 原因：当前项目已经有较强的桌面恢复和知识库逻辑，且已明确不走微调路线，最合适的方式是渐进式 runtime 融合，而不是模型训练或整体替换。
